Figure captions -- strong and weak scaling of the Hubbard propagate operator
============================================================================

LaTeX-ready captions for the figures in this directory, converted from the single
caption definition in ../captions.py -- edit that file, not this one, and re-run
make_paper_figures.py. Ranges and percentages are computed from the plotted rows, never typed.

Figs. 1-4 are the standalone single-column figures. Fig. 5 is the page-wide 2x2 composite of the
same four panels, lettered (a)-(d), for use as a single top-of-page float; it draws from the same
code, so it cannot disagree with them. Use either the four or the one, not both.

Encoding shared by every figure: colour and marker = problem size (strong) or load per node
(weak), on a light-to-dark single-hue ordinal ramp, since the three curves differ in a MAGNITUDE
rather than in identity. The x axis is cores, with the same axis repeated in nodes above -- the
two units the machine and the reader respectively think in, never a second quantity. The four
panels of the composite share one x axis, so it is drawn once per edge there: cores under the
bottom row, nodes over the top row. The figures carry no titles, so the caption is the only place
the reference lines and the machine configuration are stated.


Fig. 1  (fig-strong-time)  --  Strong scaling, wall time
--------------------------------------------------------
Strong scaling of the Hubbard propagate operator: wall time against core count, 128 to
8192 cores, at three fixed problem sizes (1.6B, 6.1B, 24.4B terms). The dotted line
beside each curve is that curve's own ideal $1/N$, anchored at its first point.
Deucalion x86, 128 cores per node, 8 MPI ranks per node with 16 partitions per rank, so
$R = 8N$ ranks at $N$ nodes. Each point is the median of five reps.


Fig. 2  (fig-strong-efficiency)  --  Strong scaling, parallel efficiency
------------------------------------------------------------------------
Strong-scaling parallel efficiency, $t(N_0)N_0 / t(N)N$, for the same runs. Each curve
is normalised to the narrowest run its problem fits in (1.6B from 128; 6.1B from 256;
24.4B from 1024 cores), so every curve begins at 100\% and the single ideal line applies
to all three; the curves therefore describe how well each size scales from that point,
and are not absolute comparisons between sizes. The departure from ideal moves to higher
core counts as the problem grows, reaching 1.6B: 14\%, 6.1B: 38\%, 24.4B: 74\% at 8192
cores. Deucalion x86, 128 cores per node, 8 MPI ranks per node with 16 partitions per
rank, so $R = 8N$ ranks at $N$ nodes. Each point is the median of five reps.


Fig. 3  (fig-weak-time)  --  Weak scaling, wall time
----------------------------------------------------
Weak scaling of the same operator: wall time against core count, 128 to 8192 cores,
holding the load per node constant at 96M (92--98M measured); 385M (377--392M measured);
1529M (1479--1569M measured) terms. The problem sizes form a sequence stepping by
$\times$1.90--2.07 rather than exactly $\times$2, so the load along a curve drifts by a
few per cent and every quantity is normalised on the measured term count. The dotted
line beside each curve is that curve's own ideal, flat from its first point. Deucalion
x86, 128 cores per node, 8 MPI ranks per node with 16 partitions per rank, so $R = 8N$
ranks at $N$ nodes. Each point is the median of five reps.


Fig. 4  (fig-weak-efficiency)  --  Weak scaling, parallel efficiency
--------------------------------------------------------------------
Weak-scaling parallel efficiency, $t(128\,\mathrm{cores}) / t(N)$, for the same runs. At
8192 cores the efficiencies are 96M/node: 29\%, 385M/node: 60\%, 1.5B/node: 84\%. The
larger the load a node carries, the closer weak scaling stays to ideal. Deucalion x86,
128 cores per node, 8 MPI ranks per node with 16 partitions per rank, so $R = 8N$ ranks
at $N$ nodes. Each point is the median of five reps.


Fig. 5  (fig-scaling-2x2)  --  All four panels, page-wide composite
-------------------------------------------------------------------
Strong and weak scaling of the Hubbard propagate operator on 128 to 8192 cores (1 to 64
nodes: the four panels share one x axis, labelled in cores under the bottom row and in
nodes over the top row). Top row, strong scaling at three fixed problem sizes (1.6B,
6.1B, 24.4B terms): (a) wall time, with each curve's own ideal $1/N$ dotted beside it,
and (b) parallel efficiency $t(N_0)N_0 / t(N)N$, each curve normalised to the narrowest
run its problem fits in, so all three begin at 100\% and the single ideal line applies
to every one --- reaching 14\%, 38\%, 74\% at 8192 cores. Bottom row, weak scaling at
three loads per node (96M, 385M, 1.5B terms/node): (c) wall time, with each curve's own
flat ideal dotted beside it, and (d) parallel efficiency $t(128\,\mathrm{cores}) /
t(N)$, reaching 29\%, 60\%, 84\% at 8192 cores. Colour and marker encode problem size
(top) or load per node (bottom); the legend in each row's efficiency panel serves both
panels of that row. Together the rows show one thing: the departure from ideal is set by
the load a node carries, not by a core count, and it moves to higher core counts as the
problem grows. Deucalion x86, 128 cores per node, 8 MPI ranks per node with 16
partitions per rank, so $R = 8N$ ranks at $N$ nodes. Each point is the median of five
reps.
