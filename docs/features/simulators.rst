Majorana and Pauli simulators
==============================

monoprop exposes **two simulators** over one Majorana engine:
``MajoranaPropagator`` for native Majorana and fermionic problems, and
``PauliPropagator`` for qubit (Pauli) problems. They share the same shape, so
switching between them changes only the *operator and gate types you author with*
and the *cutoff basis* — the way you build and evaluate a simulation is identical.

The four layers
---------------

Every problem is assembled from the same four pieces, which feed into each other
left to right:

.. code-block:: text

   Operator   ->   Gate        ->   Circuit          ->   Propagator
   (what to        (a pure           (gates + angle         (the simulator
    evolve)         generator)        values + mapping)       over the engine)

- **Operator** — the observable to evolve. A
  :class:`~monoprop.majorana_data.MajoranaOperator` (Hermitian Majorana monomials)
  or a :class:`~monoprop.pauli_data.PauliOperator` (real-coefficient Pauli
  strings).
- **Gate** — a *pure generator*: the operator whose exponential is one circuit
  layer. It carries **no** angle. :class:`~monoprop.Gate` (aliased
  :class:`~monoprop.MajoranaGate`) wraps a generator operator;
  :class:`~monoprop.PauliGate` keeps the compact local form ``(qubits, paulis)``.
- **Circuit** — an ordered sequence of gates together with the angle *values*, the
  ``parameter_mapping`` wiring each gate to an angle, and the reference
  ``initial_state``. Comes in a typed family:
  :class:`~monoprop.MajoranaCircuit`, :class:`~monoprop.PauliCircuit`, and
  :class:`~monoprop.fermi_data.FermiCircuit`.
- **Propagator** — consumes a circuit and evaluates it.

For the constructor arguments in full see :doc:`/python-api`; for cutoffs and the
Heisenberg/Schrödinger picture see :doc:`/features/cutoff` and
:doc:`/features/initialisation`.

Constructing a Majorana simulator
---------------------------------

Author the observable and gates directly in the Majorana basis. A
``MajoranaOperator`` *observable* is Hermitian, so a length-2 monomial such as
``i·m_0 m_1`` carries an imaginary coefficient. A ``MajoranaOperator`` used as a
*gate generator* instead carries its **structural (real) generator coefficients**
directly — the generator must be Hermitian, so a non-real coefficient is rejected
(see below):

.. testcode:: majorana

   from monoprop import (
       MajoranaPropagator,
       MajoranaGate,
       MajoranaCircuit,
       MajoranaOperator,
   )

   # Observable: the Hermitian monomial i·m_0 m_1 on a 2-mode system.
   observable = MajoranaOperator.from_dict({(0, 1): 1.0j}, num_modes=2)

   # Two rotation gates, each a pure generator (no angle attached). Real coefficients.
   gates = (
       MajoranaGate(MajoranaOperator.from_dict({(0,): 1.0})),      # generated by m_0
       MajoranaGate(MajoranaOperator.from_dict({(1, 2): 1.0})),    # generated by m_1 m_2
   )

   # Circuit: the gates, the angle values driving them, and the reference state.
   circuit = MajoranaCircuit(gates, parameters=(0.3, 0.7), initial_state=(0, 1))

   # Initialise the simulator, then propagate: a one-shot evolve-and-contract that
   # stores no graph (see "Driving the simulator" for the reusable-graph patterns).
   sim = MajoranaPropagator(observable, initial_state=(0, 1), cutoff=4)
   sim.propagate(circuit)

.. note::

   Gate generators must be **Hermitian**, so that exponentiating them gives a valid
   rotation. A ``MajoranaOperator`` generator must therefore have real coefficients
   (and a ``PauliGate`` a Hermitian Pauli operator); a non-real generator coefficient
   — for instance the imaginary observable convention used by mistake on a gate —
   would otherwise silently vanish, so it is rejected when the circuit is ingested:

   .. doctest:: hermiticity

      >>> from monoprop import (
      ...     MajoranaPropagator,
      ...     MajoranaGate,
      ...     MajoranaCircuit,
      ...     MajoranaOperator,
      ... )
      >>> obs = MajoranaOperator.from_dict({(0, 1): 1.0j}, num_modes=2)
      >>> sim = MajoranaPropagator(obs, initial_state=(0, 1), cutoff=4)
      >>> bad = MajoranaCircuit(
      ...     (MajoranaGate(MajoranaOperator.from_dict({(0, 1): 1.0j})),),
      ...     parameters=(0.3,),
      ... )
      >>> sim.propagate(bad)
      Traceback (most recent call last):
         ...
      ValueError: Gate generator is not Hermitian: ...

Constructing a Pauli simulator
------------------------------

The qubit front-end mirrors the Majorana one one-to-one. You author with
``PauliOperator`` observables and ``PauliGate`` gates (which keep their local
``qubits``), and the Jordan-Wigner mapping into the Majorana basis is applied for
you:

.. testcode:: pauli

   from monoprop import PauliPropagator, PauliGate, PauliCircuit, PauliOperator

   # Observable: Z⊗Z. num_qubits is given explicitly (never inferred from the strings).
   observable = PauliOperator.from_dict({"ZZ": 1.0}, num_qubits=2)

   # Two rotation gates given by their local Pauli operators and the qubits they act on.
   # The generators are Hermitian Pauli operators (real coefficients).
   gates = (
       PauliGate((0,), PauliOperator.from_dict({"X": 1.0}, num_qubits=1)),      # exp(-iθ/2 · X_0)
       PauliGate((0, 1), PauliOperator.from_dict({"ZZ": 1.0}, num_qubits=2)),   # exp(-iθ/2 · Z_0 Z_1)
   )

   # PauliCircuit needs num_qubits (it is not derivable from the local gates).
   circuit = PauliCircuit(gates, parameters=(0.3, 0.7), num_qubits=2)

   # PauliPropagator fixes the cutoff to Pauli weight and sets the JW basis change.
   sim = PauliPropagator(observable, initial_state=(), cutoff=2)
   sim.propagate(circuit)

The differences from the Majorana simulator are exactly:

.. list-table::
   :header-rows: 1
   :widths: 22 39 39

   * - Layer
     - ``MajoranaPropagator``
     - ``PauliPropagator``
   * - Observable
     - ``MajoranaOperator`` (complex-coeff Hermitian monomials)
     - ``PauliOperator`` (real-coeff Pauli strings)
   * - Gate
     - ``MajoranaGate(generator)``
     - ``PauliGate(qubits, paulis)`` — keeps local placement
   * - Circuit
     - ``MajoranaCircuit`` (no qubit count needed)
     - ``PauliCircuit`` — requires ``num_qubits``
   * - Cutoff
     - ``cutoff_type="length"`` or ``"support"``
     - fixed to ``"support"`` (Pauli weight); JW ``basis_change`` set automatically

Everything else — building the graph, evaluating expectation values and gradients,
and the shape of the results — is shared, because ``PauliPropagator`` is a subclass
of ``MajoranaPropagator``.

Driving the simulator
----------------------

The construction examples above used ``propagate`` for a single run. There are
three ways in total to feed a circuit to either simulator; all accept the same
circuits and expose the same evaluation API. The examples below use the Majorana
problem, but every call works identically on a ``PauliPropagator``.

.. testsetup:: driving

   from monoprop import (
       MajoranaPropagator,
       MajoranaGate,
       MajoranaCircuit,
       MajoranaOperator,
   )

   observable = MajoranaOperator.from_dict({(0, 1): 1.0j}, num_modes=2)
   gates = (
       MajoranaGate(MajoranaOperator.from_dict({(0,): 1.0})),
       MajoranaGate(MajoranaOperator.from_dict({(1, 2): 1.0})),
   )
   circuit = MajoranaCircuit(gates, parameters=(0.3, 0.7), initial_state=(0, 1))

**A — ``from_circuit``**: construct and build a reusable graph in one step, then
replay it at any angles.

.. doctest:: driving

   >>> sim = MajoranaPropagator.from_circuit(circuit, observable, cutoff=4)
   >>> value = sim.expectation_value(circuit)   # replay at the circuit's own angles

**B — construct, then ``build_graph``**: keep the graph and re-evaluate cheaply at
different angles (and build it incrementally across calls).

.. doctest:: driving

   >>> sim = MajoranaPropagator(observable, initial_state=[0, 1], cutoff=4)
   >>> sim.build_graph(circuit)          # the graph now owns the gates and mapping
   >>> value = sim.expectation_value([0.3, 0.7])   # evaluate at any parameter vector

**C — ``propagate``**: a one-shot contraction that stores no graph (the
memory-lean path for a single evaluation).

.. doctest:: driving

   >>> sim = MajoranaPropagator(observable, initial_state=[0, 1], cutoff=4)
   >>> sim.propagate(circuit)
   >>> evolved = sim.evolved_operator()  # dict keyed by Majorana-index tuples

Once the graph is built (pattern A or B), the full evaluation surface is available
and identical on both simulators — see :doc:`/features/evaluation`:

.. doctest:: driving

   >>> sim = MajoranaPropagator.from_circuit(circuit, observable, cutoff=4)
   >>> value, grad = sim.expectation_value_and_gradient([0.3, 0.7])
   >>> grad.shape
   (2,)

Angles and weight-tying
-----------------------

Gates never carry an angle. The circuit's ``parameter_mapping`` decides which
variational angle drives each gate; the default gives every gate its own. Reusing
an index ties gates to a shared angle:

.. testcode:: angles

   from monoprop import MajoranaGate, MajoranaCircuit, MajoranaOperator

   def gate(i):
       return MajoranaGate(MajoranaOperator.from_dict({(i,): 1.0}))

   circuit = MajoranaCircuit((gate(0), gate(1), gate(2)), parameter_mapping=(0, 1, 0))
   assert circuit.n_parameters == 2   # gates 0 and 2 share angle 0

The fermionic front-end
-----------------------

Fermionic problems reuse the Majorana simulator. A
:class:`~monoprop.fermi_data.FermiCircuit` converts its
:class:`~monoprop.fermi_data.FermiGate` generators into native
:class:`~monoprop.Gate` layers at construction, so it *is* a ``MajoranaCircuit``
and feeds ``MajoranaPropagator`` directly:

.. testcode:: fermionic

   from monoprop import MajoranaPropagator, MajoranaOperator
   from monoprop.fermi_data import FermiOperator, FermiGate, FermiCircuit

   observable = MajoranaOperator.from_dict({(0, 1): 1.0j}, num_modes=4)
   generator = FermiOperator([[(0, "+"), (0, "-")]], [1.0], num_modes=4)
   circuit = FermiCircuit(
       (FermiGate(generator),), parameters=(0.3,), initial_state=(0, 1)
   )
   sim = MajoranaPropagator.from_circuit(circuit, observable, cutoff=4)

So there are two simulators (``MajoranaPropagator``, ``PauliPropagator``) fed by
three authoring front-ends — Majorana and fermionic into ``MajoranaPropagator``,
qubit (Pauli) into ``PauliPropagator`` — all sharing one gate-expansion pipeline
and one evaluation API.
