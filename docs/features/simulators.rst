Majorana and Pauli simulators
==============================

monoprop exposes **two simulators** over one Majorana engine:
``MajoranaPropagator`` for native Majorana and fermionic problems, and
``PauliPropagator`` for qubit (Pauli) problems. They share the same shape, so
switching between them changes only the *operator and gate types you author with*
and the *cutoff basis* — the way you build and evaluate a simulation is identical.

The four layers
---------------

Every problem is assembled from the same four layers, which feed into each other
left to right:

.. code-block:: text

   Term      ->   Operator    ->   Exp gate         ->   Circuit         ->   Propagator
   (an atom:      (Σ term·coeff:   (exponentiate a       (gates + angle       (the simulator
    Majorana/      what to          generator)            values)              over the engine)
    Pauli)         evolve)

- **Term** — the atom. A :class:`~monoprop.Majorana` monomial or a
  :class:`~monoprop.Pauli` (letters on named qubits).
- **Operator** — a weighted sum of terms, written as a ``{term: coefficient}`` dict.
  A :class:`~monoprop.MajoranaOperator` (Hermitian Majorana monomials) or a
  :class:`~monoprop.PauliOperator` (real-coefficient Paulis). The observable carries
  the system width (``num_modes`` / ``num_qubits``).
- **Exp gate** — the *exponential* of a generator (a term or an operator): one
  circuit layer, driven by one angle. A single :class:`~monoprop.Exp` type infers its
  family from the generator type; a bare term is a single-term, coefficient-1 generator.
- **Circuit** — an ordered sequence of gates together with the angle *values* and the
  reference ``initial_state``. A single :class:`~monoprop.Circuit` type: the gates carry the
  family (qubit *or* Majorana/fermionic; mixing is rejected).
- **Propagator** — consumes a circuit and evaluates it, dispatching on
  :attr:`~monoprop.Circuit.family`.

For the constructor arguments in full see :doc:`/python-api`; for cutoffs and the
Heisenberg/Schrödinger picture see :doc:`/features/cutoff` and
:doc:`/features/initialisation`.

Constructing a Majorana simulator
---------------------------------

Author the observable and gates directly in the Majorana basis. A
``MajoranaOperator`` *observable* is Hermitian, so a length-2 monomial such as
``i·m_0 m_1`` carries an imaginary coefficient. A Majorana ``Exp`` gate's generator
instead carries its **structural (real) generator coefficients** directly — the
generator must be Hermitian, so a non-real coefficient is rejected (see below):

.. testcode:: majorana

   from monoprop import (
       MajoranaPropagator,
       Exp,
       Circuit,
       MajoranaOperator,
   )

   # Observable: the Hermitian monomial i·m_0 m_1 on a 2-mode system.
   observable = MajoranaOperator({(0, 1): 1.0j}, num_modes=2)

   # Two rotation gates, each the exponential of a generator. Real coefficients.
   gates = (
       Exp(MajoranaOperator({(0,): 1.0})),      # generated by m_0
       Exp(MajoranaOperator({(1, 2): 1.0})),    # generated by m_1 m_2
   )

   # Circuit: the gates, the angle values driving them, and the reference state.
   circuit = Circuit(gates, parameters=(0.3, 0.7), initial_state=(0, 1))

   # Initialise the simulator, then propagate: a one-shot evolve-and-contract that
   # stores no graph (see "Driving the simulator" for the reusable-graph patterns).
   sim = MajoranaPropagator(observable, initial_state=(0, 1), cutoff=4)
   sim.propagate(circuit)

.. note::

   Gate generators must be **Hermitian**, so that exponentiating them gives a valid
   rotation. A Majorana ``Exp`` generator must therefore have real coefficients
   (and a Pauli ``Exp`` a Hermitian Pauli operator); a non-real generator coefficient
   — for instance the imaginary observable convention used by mistake on a gate —
   would otherwise silently vanish, so it is rejected when the circuit is ingested:

   .. doctest:: hermiticity

      >>> from monoprop import (
      ...     MajoranaPropagator,
      ...     Exp,
      ...     Circuit,
      ...     MajoranaOperator,
      ... )
      >>> obs = MajoranaOperator({(0, 1): 1.0j}, num_modes=2)
      >>> sim = MajoranaPropagator(obs, initial_state=(0, 1), cutoff=4)
      >>> bad = Circuit(
      ...     (Exp(MajoranaOperator({(0, 1): 1.0j})),),
      ...     parameters=(0.3,),
      ... )
      >>> sim.propagate(bad)
      Traceback (most recent call last):
         ...
      ValueError: Gate generator is not Hermitian: ...

Constructing a Pauli simulator
------------------------------

The qubit front-end mirrors the Majorana one one-to-one. You author with
``PauliOperator`` observables and ``Exp`` gates (whose :class:`~monoprop.Pauli`
generators keep their local qubit placement), and the Jordan-Wigner mapping into
the Majorana basis is applied for you:

.. testcode:: pauli

   from monoprop import PauliPropagator, Exp, Circuit, PauliOperator, Pauli

   # Observable: Z⊗Z. num_qubits lives on the observable only.
   observable = PauliOperator({"ZZ": 1.0}, num_qubits=2)

   # Two rotation gates, each the exponential of a Pauli generator on the qubits it acts on.
   # The generators are Hermitian Pauli operators (real coefficients).
   gates = (
       Exp(Pauli("X", 0)),          # exp(-iθ/2 · X_0)
       Exp(Pauli("ZZ", (0, 1))),    # exp(-iθ/2 · Z_0 Z_1)
   )

   # The Circuit needs no qubit count — the propagator supplies it from the observable.
   circuit = Circuit(gates, parameters=(0.3, 0.7))

   # PauliPropagator fixes the cutoff to Pauli weight and sets the JW basis change.
   sim = PauliPropagator(observable, initial_state=(), cutoff=2)
   sim.propagate(circuit)

The differences from the Majorana simulator are exactly:

.. list-table::
   :header-rows: 1
   :widths: 22 39 39

   * - Layer
     - ``MajoranaPropagator``
     - ``PauliPropagator``
   * - Observable
     - ``MajoranaOperator`` (complex-coeff Hermitian monomials)
     - ``PauliOperator`` (real-coeff Paulis; carries ``num_qubits``)
   * - Gate
     - ``Exp(MajoranaOperator | FermiOperator)``
     - ``Exp(PauliOperator)`` — ``Pauli`` terms keep local placement
   * - Circuit
     - ``Circuit`` of Majorana/fermionic ``Exp`` gates (``family == "majorana"``)
     - ``Circuit`` of Pauli ``Exp`` gates (``family == "pauli"``; no qubit count)
   * - Cutoff
     - ``cutoff_type="length"`` or ``"support"``
     - fixed to ``"support"`` (Pauli weight); JW ``basis_change`` set automatically

Everything else — building the graph, evaluating expectation values and gradients,
and the shape of the results — is shared, because ``PauliPropagator`` is a subclass
of ``MajoranaPropagator``.

Driving the simulator
----------------------

The construction examples above used ``propagate`` for a single run. There are
three ways in total to feed a circuit to either simulator; all accept the same
circuits and expose the same evaluation API. The examples below use the Majorana
problem, but every call works identically on a ``PauliPropagator``.

.. testsetup:: driving

   from monoprop import (
       MajoranaPropagator,
       Exp,
       Circuit,
       MajoranaOperator,
   )

   observable = MajoranaOperator({(0, 1): 1.0j}, num_modes=2)
   gates = (
       Exp(MajoranaOperator({(0,): 1.0})),
       Exp(MajoranaOperator({(1, 2): 1.0})),
   )
   circuit = Circuit(gates, parameters=(0.3, 0.7), initial_state=(0, 1))

**A — ``from_circuit``**: construct and propagate in one step (in-place, storing no
graph) -- the one-line form of pattern C. The circuit's angles are applied during the
call, so the result is read off with a **no-argument** ``evolved_operator()`` /
``expectation_value()``.

.. doctest:: driving

   >>> sim = MajoranaPropagator.from_circuit(circuit, observable, cutoff=4)
   >>> value = sim.expectation_value()   # angles already applied in-place

**B — construct, then ``build_graph``**: keep the graph and re-evaluate cheaply at
different angles (and build it incrementally across calls).

.. doctest:: driving

   >>> sim = MajoranaPropagator(observable, initial_state=[0, 1], cutoff=4)
   >>> sim.build_graph(circuit)          # the graph now owns the gates and mapping
   >>> value = sim.expectation_value([0.3, 0.7])   # evaluate at any parameter vector

**C — ``propagate``**: a one-shot contraction that stores no graph (the
memory-lean path for a single evaluation).

.. doctest:: driving

   >>> sim = MajoranaPropagator(observable, initial_state=[0, 1], cutoff=4)
   >>> sim.propagate(circuit)
   >>> evolved = sim.evolved_operator()  # dict keyed by Majorana-index tuples

Only a **built graph** (pattern B) can be re-evaluated at new angles or
differentiated; the in-place paths (A and C) evolve once at the circuit's own angles.
With a graph the full evaluation surface is available and identical on both simulators
— see :doc:`/features/evaluation`:

.. doctest:: driving

   >>> sim = MajoranaPropagator(observable, initial_state=[0, 1], cutoff=4)
   >>> sim.build_graph(circuit)
   >>> value, grad = sim.expectation_value_and_gradient([0.3, 0.7])
   >>> grad.shape
   (2,)

Angles and weight-tying
-----------------------

Each gate is the unit of parameterization: one gate is driven by one angle, named
by its ``param`` index. With no gate setting ``param`` each gate gets its own angle;
giving two gates the same ``param`` ties them to a shared angle:

.. testcode:: angles

   from monoprop import Exp, Circuit, MajoranaOperator

   def gate(i, param):
       return Exp(MajoranaOperator({(i,): 1.0}), param=param)

   circuit = Circuit((gate(0, 0), gate(1, 1), gate(2, 0)))
   assert circuit.n_parameters == 2   # gates 0 and 2 share angle 0

The fermionic front-end
-----------------------

Fermionic problems reuse the Majorana simulator. An :class:`~monoprop.Exp` gate built
from a :class:`~monoprop.fermi_data.FermiOperator` is converted into a structural
Majorana :class:`~monoprop.Exp` layer at :class:`~monoprop.Circuit` construction, so the
circuit is ``"majorana"``-family and feeds ``MajoranaPropagator`` directly:

.. testcode:: fermionic

   from monoprop import Circuit, MajoranaPropagator, MajoranaOperator
   from monoprop import Exp
   from monoprop.fermi_data import FermiOperator

   observable = MajoranaOperator({(0, 1): 1.0j}, num_modes=4)
   generator = FermiOperator([[(0, "+"), (0, "-")]], [1.0], num_modes=4)
   circuit = Circuit(
       (Exp(generator),), parameters=(0.3,), initial_state=(0, 1)
   )
   sim = MajoranaPropagator.from_circuit(circuit, observable, cutoff=4)

So there are two simulators (``MajoranaPropagator``, ``PauliPropagator``) fed by
three authoring front-ends — Majorana and fermionic into ``MajoranaPropagator``,
qubit (Pauli) into ``PauliPropagator`` — all sharing one gate-expansion pipeline
and one evaluation API.
