[MareNostrum5](https://www.bsc.es/supportkc/docs/MareNostrum5/intro) (MN5) at BSC has no
outbound network on its login nodes, so run monoprop from the
[container image](/clusters): pull it on a machine with internet access, copy it over, and
launch it with Singularity under Slurm. The image targets the Sapphire Rapids CPUs of both
the general-purpose (GPP) and accelerated (ACC) partitions.

## Get the image

The image is public, so no registry login is needed. On a machine with internet access
and Singularity (or Apptainer) installed:

```bash
singularity pull monoprop_<tag>.sif docker://ghcr.io/algorithmiq/monoprop:<tag>
```

Copy the `.sif` file (the image is about 1.3 GB unpacked; the `.sif` is compressed and
smaller) to your project directory on MN5 with `scp` or `rsync` through a login or
data-transfer node, for example:

```bash
rsync -P monoprop_<tag>.sif <user>@<mn5-host>:<project-dir>/
```

## Check the image

From an allocation on a compute node, check that monoprop imports and sees MPI on two
ranks:

```bash
module load singularity
srun -n 2 --mpi=pmix singularity exec monoprop_<tag>.sif \
    python3 -c 'import monoprop; print(monoprop.__version__, monoprop.has_mpi)'
```

Both ranks should print the image's version and `True`. This is the check CI cannot run:
the CI machines may lack the Sapphire Rapids instructions the image is compiled for.

## Run a job

Adapt this script and submit it with `sbatch`. The account and QoS can also be given on
the command line.

```bash
#!/usr/bin/env bash

#SBATCH --job-name=monoprop  # <-- CHANGE ME
#SBATCH --chdir=.
#SBATCH --exclusive
#SBATCH --ntasks-per-node=8
#SBATCH --cpus-per-task=14
#SBATCH --threads-per-core=1
#SBATCH --output=%x-%j.out
#SBATCH --error=%x-%j.err

# GIVEN THROUGH THE COMMAND LINE
##SBATCH --partition=gpp
##SBATCH --account=<account>
##SBATCH --nodes=2
##SBATCH --time=06:00:00
##SBATCH --qos=<qos>

module purge
module load singularity/4.1.5
module list

#----
# Printing the status of the given allocation
echo -e "\n\n#------------------------#"
echo "Printing from scontrol:"
scontrol show job "${SLURM_JOBID}"

export SRUN_CPUS_PER_TASK=$SLURM_CPUS_PER_TASK

echo -e "\n\n#------------------------#"
echo "Diagnostic for task distribution (with task and taskset):"
srun \
    --label \
    --verbose \
    --mpi=pmix \
    --nodes="$SLURM_NNODES" \
    --ntasks="$(( SLURM_NTASKS_PER_NODE * SLURM_NNODES))" \
    --ntasks-per-node="$SLURM_NTASKS_PER_NODE" \
    --threads-per-core=1 \
    --cpu-bind="verbose,threads" \
    --hint nomultithread \
    --distribution=block:block \
    bash -c 'echo -n "task $SLURM_PROCID (node name: $(hostname), node id: $SLURM_NODEID): "; taskset -cp $$' | sort -n

# An MPI rank keeps a single partition unless monoprop_NUM_THREADS is set.
export monoprop_NUM_THREADS="$SLURM_CPUS_PER_TASK"
# Directories the container may read and write besides $HOME and the working directory.
export SINGULARITY_BIND="/gpfs/projects,/gpfs/scratch,$TMPDIR"

####### HERE we actually run monoprop #######
srun \
    --label \
    --verbose \
    --mpi=pmix \
    --nodes="$SLURM_NNODES" \
    --ntasks="$(( SLURM_NTASKS_PER_NODE * SLURM_NNODES))" \
    --ntasks-per-node="$SLURM_NTASKS_PER_NODE" \
    --threads-per-core=1 \
    --cpu-bind="verbose,threads" \
    --hint nomultithread \
    --distribution=block:block \
    --kill-on-bad-exit=1 \
    singularity exec monoprop_<tag>.sif \
    python3 -u run.py  # <-- CHANGE ME
###########################################

#----
# Printing information of finished job steps:
echo -e "\n\n#------------------------#"
echo "Task and CPU usage stats:"
sacct --format=JobID,JobName,NCPUS,NNodes,NTasks,AveCPU,MinCPU,MinCPUNode,MinCPUTask,Elapsed,ExitCode --jobs="$SLURM_JOBID"

echo "Memory usage stats:"
sacct --format=JobID,JobName,AveRSS%-50,MaxRSS%-50,MaxRSSNode,MaxRSSTask,AvePages,MaxPages,MaxPagesNode,MaxPagesTask --units=M --jobs="$SLURM_JOBID"

echo "Disk usage stats:"
sacct --format=JobID,JobName,AveDiskRead,MaxDiskRead,MaxDiskReadNode,MaxDiskReadTask,AveDiskWrite,MaxDiskWrite,MaxDiskWriteNode,MaxDiskWriteTask --units=G --jobs="$SLURM_JOBID"

echo "Trackable resources usage stats:"
sacct --format=JobID,JobName,AllocNodes,AllocCPUS,AllocTRES%-100 --units=G --jobs="$SLURM_JOBID"

echo "Trackable resources (ingress) usage stats:"
# ingress resources are disk reads and network incoming transfers
sacct --format=JobID,JobName,TRESUsageInTot%-70,TRESUsageInAve%-70,TRESUsageInMax%-70,TRESUsageInMaxNode%-70,TRESUsageInMaxTask%-70 --units=G --jobs="$SLURM_JOBID"

echo "Trackable resources (egress)  usage stats:"
# egress resources are disk writes and network outgoing transfers
sacct --format=JobID,JobName,TRESUsageOutTot%-70,TRESUsageOutAve%-70,TRESUsageOutMax%-70,TRESUsageOutMaxNode%-70,TRESUsageOutMaxTask%-70 --units=G --jobs="$SLURM_JOBID"

#----
# Done
echo -e "\n\n#------------------------#"
echo "Done
```

- `--exclusive`: MN5 only honours CPU affinity on full nodes.
- `--ntasks-per-node` × `--cpus-per-task` should fill a GPP node's 112 cores (2 sockets of
  56), with each rank inside one socket. `--distribution=block:block` hands each rank
  consecutive cores.
- `--cpu-bind=cores` binds each rank to its cores. monoprop pins one partition per core
  inside the mask it is given, so the binding and `monoprop_NUM_THREADS` together decide
  how many partitions each rank runs; see [Parallelism and distribution](/features/parallelism).

### Check the placement

Every rank prints a `COMMPLACE` line to stderr when it builds a propagator. With the script
above it reads `masks=private cpus=56`: the ranks on a node have disjoint masks of 56 CPUs.
To check the binding before running monoprop:

```bash
srun --mpi=pmix --cpu-bind=cores --distribution=block:block \
    grep Cpus_allowed_list /proc/self/status
```

### Tune UCX

The container brings its own UCX, so `module load ucx` on the host has no effect; set UCX
through environment variables, which Singularity passes into the container. With many
ranks per node, select the dynamically connected transport, since `rc_mlx5` can run out
of network-device memory at scale:

```bash
export UCX_TLS=self,sm,dc_mlx5
```

To list the transports UCX sees on a compute node:

```bash
srun -n 1 singularity exec "$image" ucx_info -d | grep Transport -A2
```

Launch with `srun` as above rather than `mpirun`; `mpirun` inside an allocation also needs
`SLURM_CPU_BIND=none`.
